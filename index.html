An Efficient CNN-LSTM Model for Urban Traffic Speed Forecasting

Question 1: What is the input source for the project and from where it is taken?
Answer: Image dataset
Question 2: What are all the features of detecting traffic?
Answer:
  • Spatial Vehicle Distribution
  • Inter-vehicle distance (bounding box spatial relationships)
  • Average Speed
  • Historical Velocity Trends over 5-minute time steps
Question 3: From where the features are collected? How the features are extracted? What tool is used for feature extraction?
Answer:
WHERE? Kaggle/Caltrans datasets
HOW? For Traffic Density, Vehicle Positions, Lane Occupancy: 2D Convolutional layers (Conv2D with 3x3 kernels)
For Speed Changes Over Time: LSTM Network with 128 Units
TOOLS: PyTorch, TensorFlow / Keras, NumPy, and Scikit-learn
WHY? PeMS is the standard, globally accepted real-world traffic benchmark that provides reliable, high-quality, continuous traffic sensor records collected across California highway networks, making it ideal for testing spatiotemporal models without needing hardware installations
Question 4: How the features are extracted? What tool is used for feature extraction?
Answer:
  1. PyTorch
    • Builds and runs the Conv2D layers (to extract spatial features like vehicle density and placement).
    • LSTM layers (to extract temporal velocity sequences over time) using GPU acceleration.
  2. TensorFlow / Keras
    • Provides high-level neural network modules to construct, train, and extract feature representations from intermediate layers of the CNN-LSTM architecture.
  3. NumPy
    • Handles raw dataset reshaping, multidimensional tensor operations (T × H × W × C), sliding window creation, and array processing before feeding features into deep learning models.
  4. Scikit-learn
    • Performs feature scaling, data normalization (MinMax/Standard scaling), train-test dataset splitting, and feature selection (such as Mutual Information Regression).
Question 5: Using CNN, how the features are extracted?
Answer:
  1. First Conv2D Layer (3 × 3, ReLU): Captures local spatial relationships, such as vehicle positions and immediate road density.
  2. Second Conv2D Layer (3 × 3, ReLU): Captures complex inter-vehicle spacing and broader road segment structures.
  3. MaxPooling2D Layer (2 × 2): Downsamples feature maps by 50%, reducing spatial dimensions while retaining critical traffic structure data.
Question 6: On what basis the model classifies the data that it recieves?
Answer: The model performs regression rather than discrete classification. It estimates future traffic speed based on learned spatiotemporal embeddings—evaluating the correlation between vehicle density/spacing (extracted by CNN) and past velocity dynamics (modeled by LSTM).
Question 7: What is the augumentation and range of the classification?
Answer:
  1. Augmentation:
    • Temporal sliding window slicing
    • Feature normalization/scaling
    • Random sequence jittering
    • Sequence masking
  1. Range & Output:
    2. Continuous numerical speed forecast from 0 to 120 km/h (or mph)
    Categorized into 4 levels:
    • Free
    • Flow Slow
    • Traffic Congested Heavy
    • Bottleneck
Question 8: What are the methods used for vehicle identification?
Answer:
  1. CNN Feature Extraction: Passes video frame matrices through Conv2D layers (3 × 3 kernels) to learn vehicle patterns, shapes, and spatial density without physical hardware sensors
  2. Bounding Box Analysis: Evaluates spatial bounding box coordinates across consecutive frame sequences to calculate inter-vehicle spacing and positional distribution
  3. Dataset Metric Analytics: Processes pre-recorded software traffic logs (flow volume, speed, and lane occupancy rates) directly from the PeMS dataset files
Question 9: What are all the features of detecting weather?

Question 10: What is the refresh rate for the live video?
Answer: 15 to 30 FPS (Frames Per Second) with 5-minute sliding time windows for traffic speed forecasting
Question 11: What is the range for the live video? What are the levels for the live video? From that, how the frames are taken?
Answer:
  1. Range: Covers a 50 to 200 meter visible stretch of road per camera.
  2. Levels: Captures both close-range vehicle spacing (micro level) and overall road traffic density (macro level).
  3. Frame Extraction: Video plays at 15 to 30 frames per second (FPS), and software samples 1 frame at regular time intervals (e.g., every 5 seconds) to build input data sequences.
Question 12: What is the format of dataset?
Answer:
  1. .npz format for storing multi-dimensional traffic arrays (speed, flow, and occupancy combined)
  2. .csv format for structured time-series speed and traffic logs
1. .npz Format (Numpy Zipped Files):

Used in the Model Training & Feature Extraction Pipeline (Data Preprocessing Module).
Stores the combined multi-dimensional traffic arrays containing Speed, Flow Volume, and Lane Occupancy across all detector stations and time steps.
.npz is used because, it compresses large multi-dimensional NumPy arrays into a single, light file without losing data precision.
It keeps multiple related datasets (e.g., speed, flow, occupancy) grouped together under one file using simple keys.
Data is stored as .npz for my project because, Deep learning models (CNN and LSTM) require input data in 3D tensor shapes (Time Steps x Detector Stations x Features).
.npz natively preserves these multi-dimensional shapes.
It loads directly into Python memory instantly as NumPy arrays without requiring slow text parsing.

2. .csv Format (Comma Separated Values):

Used in the Input Data & Output Logging Modules (and raw dataset inspection).
Stores 2D time-series traffic logs, historical speed sequences, and final predicted speed outputs for display on the React frontend/Flask backend.
.csv is used because, it is simple and human-readable (columns and rows).
Supported by almost all tools and libraries like Pandas and Excel.
Perfect for flat, sequential time-series data where each row represents a timestamp and each column represents a traffic attribute or sensor ID.
Data is stored as .csv for your project because, it is ideal for viewing, logging and passing structured 2D traffic time-series records into data analysis tools like Pandas for feature scaling and visualization.
Easily integrates with web backend frameworks (Flask/PostgreSQL) to export or render final predicted speed results to the user interface.
Question 13: Why do these formats used specifically?
Answer: If .npz is NOT used...

Data Shape Loss: Standard text files cannot naturally hold 3D/4D matrix structures, forcing you to write complex, slow code to reconstruct the array dimensions every time. Memory Overhead & Slow Training: Training will slow down significantly because loading large raw traffic matrices will take much longer and use much more RAM.

If .csv is NOT used...

Loss of Readability: You won't be able to easily open, inspect, or audit raw input logs and predicted speed outputs using simple tools like Excel or standard text editors. Integration Complexity: Exporting model predictions to the frontend or database will require extra custom conversion steps instead of standard tabular file parsing.
Question 14: What are the security measures taken to develop this project?
Answer:
  1. Input Validation: Sanitizes and validates all uploaded video and dataset files to prevent malicious code execution or file format exploits.
  2. API Security: Uses JWT (JSON Web Tokens) for authenticated and encrypted communication between the React frontend and Flask backend.
  3. Database Access Control: Implements Role-Based Access Control (RBAC) in PostgreSQL/MongoDB to protect system records and user logs from unauthorized access.
  4. Environment Protection: Safely stores database credentials, secret keys, and configuration parameters in .env environment files instead of hardcoding them into the codebase.
